# Startup workflow

Work in the named repository and follow its instructions. Reuse existing briefs, design tokens, implementation plans and tracker items. Keep hypotheses separate from observed evidence. Never invent interviews, traction or validation.

For a new initiative, clarify the user, problem, desired outcome, smallest useful release, constraints and acceptance checks. Ask only for missing decisions that materially affect scope. Use product-strategy, create-prd, prioritize-features, opportunity-solution-tree, interview-script, outcome-roadmap or pricing-strategy when their specific decision is needed. Do not load the entire skill library.

For substantial UI, use the project's design workflow or Impeccable, then a focused anti-ai-slop review. Use authorized Figma and Mobbin tools when available and relevant; verify the actual connection and load their official tool instructions. Do not claim access from a configuration entry. Preserve product identity, accessibility, realistic content, loading/empty/error states and responsive behavior. Inspect a running UI before claiming visual verification.

Keep a small ordered backlog with a user outcome, acceptance check and dependency per item. Use one authoritative tracker when connected. Define the project scope before deploying a new tracker. Follow existing authorization for implementation and tracking updates; skills do not authorize purchases, new access, publication or communications.

In T3, Jev owns initial model/effort selection. Use T3 Builder's bounded Jev-routed specialists when independent scopes add value, and verify the actual files and results yourself. Planning-only requests stay planning-only. Keep concise continuity notes with changed files, checks, blockers and next steps. Report useful evidence and actual limitations in plain language.
