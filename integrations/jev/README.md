# Jev Auto for T3 Code

Jev selects a connected native agent, its model and effort, relevant skills, and a proportional collaboration approach. The coordinating agent can use bounded Jev-routed specialists. The custom T3 client shows a visible agent panel with current steps, reported completion checkmarks, nested specialists and exact model/effort selections. The addon also sends readable checklists for older clients. Approvals and questions are forwarded from the bound task family. In the custom client, child-agent questions appear expanded above the main message box, with choices and a direct answer form; opening the child chat is optional.

Start with [macOS setup](docs/macos-setup.md). An existing OpenRouter API connection can also join the routing pool; see [OpenRouter setup](docs/openrouter.md). Install the single pinned dependency with `npm ci --ignore-scripts`; `node macos-setup.mjs check` is read-only, and `node macos-setup.mjs install --set-default` registers the addon. Each person connects their own native providers/MCP tools and supplies their own sensitive `TYPESAFE_API_KEY` in T3. Existing Macs can deliberately reuse their own pre-existing Pi or Keychain Jev credential store; those stores are never copied into this package.

**Use T3 permissions** is an informational ACP mode. T3's actual **Permissions** control is authoritative. **Full access** skips routine command/edit prompts; **Auto** can still ask with some providers. Native plan-only mode, sign-ins and genuine questions remain meaningful.

Planning mode is opt-in; Jev does not turn it on from its task classification or automatically load an implementation-planning workflow for coding. Ordinary requests follow the requested work directly. Use **`/plan`** to stay in planning mode, or **`/plan your task`** to start a plan immediately. Jev passes native plan mode to every selected executor, including quota handoffs. Use **`/build`** to return to implementation under your existing T3 permissions. Mode commands do not change or interrupt an attached task; finish or cancel it first.

If a provider reports a confirmed usage limit, Jev stops its task and descendants before selecting another eligible connection, carries the original request and prior activity forward, and temporarily excludes that connection for 30 minutes. A chain is bounded to six attempts. Ordinary errors, sign-in failures and permission requests need attention. Quota balances are not known in advance. Antigravity and direct Claude are separate connections; an Antigravity limit is reported as Antigravity. Older T3 releases require a matching native Antigravity error record to verify their completed quota banner; quoted assistant text alone never triggers a switch.

The 33 starter skill folders retain their source records and licenses. Existing user-installed skills take precedence; bundled skills are a fallback. No accounts, API keys, chat databases, local runtime state, personal project material or machine-specific API wrappers are included. The addon follows the repository's MIT license; third-party skills retain their own license and NOTICE terms.

Run `npm test` and `npm run audit`. Maintainers regenerate `files.sha256.json` with `node verify-export.mjs --update` after intended changes and check the staged public file set with `node verify-export.mjs --tracked`. Do not format vendored skills or normalize their bytes. The tested live T3 API is the installed 0.1.6 beta; verify compatibility when updating it. A native panel requires the custom desktop build; installing only the addon does not replace stock T3’s interface. The separately packaged Jev T3 app uses its own profile and disables upstream automatic updates. Each person supplies their own accounts and keys. Attachment forwarding and universal MCP parity are not implemented.
